# System Monitoring 2.0.0

System Monitoring 2.0.0 turns the original experiment into a self-hosted workspace for
small teams and isolated customer pilots. It follows approved HTTP services from a
scheduled observation through an incident, notification delivery and recovery.

## Included

- Responsive administrator workspace with service configuration, incident history,
  response-time charts and observed-success context.
- Revocable administrator sessions, CSRF protection, login throttling and local account
  recovery.
- Bounded scheduled probes with exact-origin approval, persistent observations,
  failure thresholds and recovery.
- Durable generic webhook events with stable IDs, at-least-once delivery and visible
  retry status.
- Prometheus metrics, a provisioned Grafana dashboard and controlled outage scenario.
- Consistent SQLite backup and validated restore tooling.
- Optional Caddy HTTPS deployment for one isolated installation.
- Public product website with real screenshots and a recorded interface walkthrough.

## Install or upgrade

For a fresh local installation, copy `.env.example`, choose unique credentials and
approve exact monitoring origins before running `docker compose up --build -d`. Create
the administrator interactively with `python -m system_monitoring.admin` inside the
application container.

Before upgrading, record the current image digest and create a consistent database
backup with `python -m system_monitoring.backup backup`. Version 2.0.0 migrates older
schema 1 and 2 databases to schema 3 on startup. Rollback requires the previous image
and its matching pre-upgrade database snapshot. Read [backup and rollback](../backups.md)
and the [HTTPS deployment runbook](../deployment.md) before a pilot deployment.

## Known limits

The release supports one administrator, one application process and one customer per
installation. SQLite has no built-in failover. Availability summaries describe retained
valid checks rather than continuous uptime. Webhook delivery is at least once, so
receivers must deduplicate the stable event ID. Multi-tenant accounts, billing,
distributed collectors and high availability remain future work.
